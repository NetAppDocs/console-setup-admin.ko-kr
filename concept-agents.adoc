[role="lead"]
콘솔 에이전트는 스토리지 인프라를 NetApp 콘솔에 연결하기 위해 네트워크에 설치하는 경량 소프트웨어 구성 요소입니다. 이를 통해 고급 스토리지 오케스트레이션, 데이터 서비스 및 안전한 클라우드 통합이 가능합니다.



== Console 에이전트의 역할

콘솔 에이전트는 스토리지 시스템과 NetApp Console 간의 연결 격차를 해소합니다. 인프라를 NetApp API 및 Console에 안전하게 연결하여 다음과 같은 작업을 수행할 수 있도록 지원합니다.

* NetApp Console을 통해 AWS, Azure, Google Cloud 및 온프레미스 환경 전반의 스토리지 시스템을 검색하고 모니터링할 수 있습니다.
* NetApp Console에서 스토리지 시스템의 스토리지 프로비저닝 및 구성 작업을 오케스트레이션합니다.
* 지능형 데이터 보호 및 관리 워크플로를 사용하십시오.
* 클라우드 서비스 사용량을 안전하게 추적하고 배포를 올바른 구독에 연결하여 정확한 청구 및 비용 관리를 실현하세요.




=== Console 에이전트 아키텍처

에이전트는 다음과 같은 경량 프로세스로 작동합니다.

* NetApp Console SaaS 애플리케이션에서 데이터를 가져오거나 내보냅니다(표준 및 제한된 모드)
* 모든 통신 시작 - NetApp Console은 에이전트에 대한 아웃바운드 호출을 시작하지 않습니다
* 표준 관리 프로토콜을 사용하여 스토리지 시스템에 연결하십시오
* 클라우드 공급자 및 NetApp Console API와의 안전한 통신을 위해 TLS 1.3을 사용하십시오




=== Console 에이전트 가용성 및 운영 요구 사항

콘솔 에이전트는 NetApp Console에 매우 중요합니다. 중단 없는 관리 및 데이터 서비스를 위해서는 에이전트가 항상 작동 가능하고 접근 가능해야 합니다. 따라서 다음 사항을 보장해야 합니다.

* 에이전트는 계속 실행됩니다
* 에이전트는 필요한 엔드포인트에 대한 네트워크 연결을 가지고 있습니다.
* 인프라 장애는 신속하게 해결됩니다.
* 에이전트 VM은 NetApp 권장 사항에 따라 유지 관리 및 업그레이드됩니다




== Console 에이전트가 필요할 때

다음과 같은 작업을 수행하려면 NetApp Console 에이전트를 하나 이상 배포해야 합니다.

* 제한된 모드 또는 비공개 배포 모드(사용자 환경에 NetApp Console 설치)를 사용하십시오. 일부 서비스를 활성화하려면 추가 에이전트가 필요할 수 있습니다.
* 고급 데이터 서비스(NetApp Backup and Recovery, NetApp Disaster Recovery, NetApp Ransomware Resilience, NetApp Data Classification 등)에 액세스할 수 있습니다.
* Cloud Volumes ONTAP 시스템을 관리합니다.
* 온프레미스 ONTAP 클러스터에서 고급 관리 작업을 수행합니다.
* 라이센스를 추적하고, 스토리지 상태를 모니터링하고, 수명 주기 업그레이드를 계획하세요.


에이전트 없이도 기본적인 스토리지 검색과 제한된 모니터링 및 스토리지 관리 기능을 사용할 수 있습니다. 하지만 대부분의 엔터프라이즈 사용 사례에서는 하나 이상의 운영 에이전트가 필요합니다.

== NetApp Console 에이전트 배포 옵션

NetApp Console 에이전트는 다음 위치에 배포할 수 있습니다.

* 아마존 웹 서비스
* 마이크로소프트 애저
* 구글 클라우드
+
Google Cloud 리소스를 관리하려면 Google Cloud에 에이전트를 배포하세요. 온프레미스 에이전트는 Google Cloud 리소스를 관리할 수 없습니다.

* 귀사 사업장에서(표준 또는 프라이빗 모드만 해당)


Console 배포 모드, 스토리지 환경 및 데이터 주권 요구 사항에 따라 에이전트 배포 위치가 결정됩니다. 조직 분리 또는 비즈니스 요구 사항에 따라 여러 환경에 에이전트를 배포할 수 있습니다.

Console, 클라우드 마켓플레이스 또는 VCenter나 온프레미스 환경에서 수동으로 에이전트를 배포할 수 있습니다. link:concept-agent-install-options.html["배포 방법을 비교하여 환경에 맞는 방법을 선택하십시오"].



=== NetApp Console SaaS 애플리케이션용 에이전트(표준 모드)

클라우드 또는 온프레미스에 에이전트를 배포하여 클라우드에서 호스팅되는 Console SaaS 애플리케이션과의 연결을 구축하세요. 에이전트를 통해 고급 기능을 사용할 수 있으며, Console UI는 어디서든 접속 가능합니다.

SaaS 애플리케이션(표준 모드)을 사용하는 경우 NetApp Console에서 에이전트를 직접 설치할 수 있습니다. AWS, Azure 또는 Google Cloud에 설치하거나 자체 Linux 호스트 또는 VCenter 환경의 온프레미스에 수동으로 설치할 수 있습니다.



=== 제한된 모드의 NetApp Console용 에이전트

제한된 모드에서 사용자는 클라우드 기반 SaaS 애플리케이션이 아닌 설치된 에이전트에서 직접 NetApp Console에 액세스합니다. Console 액세스 지점 역할을 하는 에이전트를 하나 이상 설치해야 합니다. 데이터 서비스를 활성화하고 스토리지 시스템을 관리하려면 추가 에이전트가 필요합니다.

클라우드 공급자의 마켓플레이스에서 에이전트를 설치하거나 클라우드, 사내 또는 VCenter 환경의 자체 Linux 호스트에 소프트웨어를 수동으로 설치합니다.



=== 프라이빗 모드(온프레미스 또는 클라우드 환경에서 아웃바운드 연결이 없는 경우)의 NetApp Console용 에이전트

개인 모드에서 사용자는 설치된 에이전트에서 직접 NetApp Console에 액세스합니다. Console 액세스 지점 역할을 하는 에이전트를 하나 이상 설치해야 합니다. 데이터 서비스를 활성화하고 스토리지 시스템을 관리하려면 추가 에이전트가 필요합니다.

데이터 센터 또는 에어갭 환경에 에이전트를 설치하십시오. 에이전트는 NetApp API 엔드포인트에 연결되지 않으며 모든 작업은 로컬에서 수행되므로 데이터 주권과 제어권을 완벽하게 유지할 수 있습니다.



=== 필요한 경우 여러 에이전트 사용

각 에이전트는 독립적으로 작동하며 여러 스토리지 시스템과 데이터 서비스를 관리할 수 있습니다. 다음과 같은 경우 여러 에이전트를 배포합니다.

* 스토리지 유형 또는 조직 기능별 격리
* 지리적 또는 네트워크 세그먼트화 요구 사항


예를 들어:

* 멀티클라우드 환경에서는 AWS에 에이전트 하나와 Azure에 에이전트 하나를 배포할 수 있습니다. 각 에이전트는 해당 환경에서 Cloud Volumes ONTAP 시스템을 관리합니다.
* 서비스 공급자는 고객에게 서비스를 제공하기 위해 하나의 Console 조직을 사용하고 사업부의 재해 복구를 위해 다른 조직을 사용할 수 있습니다. 각 조직에는 자체 에이전트가 필요합니다.




== 콘솔 에이전트 업그레이드

클라우드의 에이전트는 아웃바운드 인터넷 액세스가 있을 때 자동으로 업그레이드됩니다. 인터넷 액세스가 없는 에이전트(프라이빗 모드)의 경우 수동 업그레이드 지침은 link:task-upgrade-agent.html["콘솔 에이전트 업그레이드 관리"]을 참조하십시오.
