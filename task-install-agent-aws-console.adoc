= NetApp Console에서 AWS에 Console 에이전트 배포
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Console을 벗어나지 않고 AWS에 콘솔 에이전트를 배포하여 AWS 리소스 및 데이터 서비스 관리를 시작할 수 있습니다.

AWS에 Console 에이전트를 배포하면 사용자가 선택한 VPC에서 Linux 및 Console 에이전트 소프트웨어가 실행되는 EC2 인스턴스가 시작됩니다.

.시작하기 전에
* link:concept-agent-install-options.html#agent-console-deploy["NetApp Console에서 배포해야 하는 시점을 알아보세요."].
* 검토link:reference-limitations.html["콘솔 에이전트 제한 사항"] .

== 1단계: AWS에 콘솔 에이전트를 배포하기 위한 네트워킹 설정

Console 에이전트를 배포할 네트워크 위치가 다음 요구 사항을 충족하는지 확인하십시오. 이러한 요구 사항을 충족해야 Console 에이전트가 하이브리드 클라우드의 리소스 및 프로세스를 관리할 수 있습니다.

VPC 및 서브넷:: 콘솔 에이전트를 생성할 때는 에이전트가 상주해야 하는 VPC와 서브넷을 지정해야 합니다.


대상 네트워크에 대한 연결:: 콘솔 에이전트를 사용하려면 시스템을 만들고 관리하려는 위치에 대한 네트워크 연결이 필요합니다.  예를 들어, Cloud Volumes ONTAP 시스템이나 온프레미스 환경의 스토리지 시스템을 만들 계획인 네트워크입니다.


아웃바운드 인터넷 접속:: 콘솔 에이전트를 배포하는 네트워크 위치에는 특정 엔드포인트에 연결하기 위한 아웃바운드 인터넷 연결이 있어야 합니다.


콘솔 에이전트에서 연락한 엔드포인트:: 콘솔 에이전트는 일상 업무를 위해 퍼블릭 클라우드 환경 내의 리소스와 프로세스를 관리하기 위해 다음 엔드포인트에 연결하기 위해 아웃바운드 인터넷 액세스가 필요합니다.
+
--

NetApp 콘솔에서 연결된 엔드포인트:: 웹 기반 NetApp Console SaaS 애플리케이션을 사용하면 데이터 관리 작업을 완료하기 위해 여러 엔드포인트에 연결합니다. 여기에는 Console에서 Console 에이전트를 배포하기 위해 연결하는 엔드포인트도 포함됩니다.
+
--
link:reference-networking-saas-console.html["NetApp Console에서 연결된 엔드포인트 목록을 확인하십시오"].

--


프록시 서버:: NetApp 명시적 프록시 구성과 투명 프록시 구성을 모두 지원합니다.  투명 프록시를 사용하는 경우 프록시 서버에 대한 인증서만 제공하면 됩니다.  명시적 프록시를 사용하는 경우 IP 주소와 자격 증명도 필요합니다.
+
--
* IP 주소
* 신임장
* HTTPS 인증서


--


포트:: Console 에이전트로 들어오는 트래픽은 사용자가 직접 시작하거나 Cloud Volumes ONTAP에서 NetApp Support로 AutoSupport 메시지를 보내기 위한 프록시로 사용되는 경우를 제외하고는 없습니다.
+
--
* HTTP(80) 및 HTTPS(443)는 로컬 UI에 대한 액세스를 제공하며 이는 드문 상황에서 사용됩니다.
* SSH(22)는 문제 해결을 위해 호스트에 연결해야 하는 경우에만 필요합니다.
* 아웃바운드 인터넷 연결을 사용할 수 없는 서브넷에 Cloud Volumes ONTAP 시스템을 배포하는 경우 포트 3128을 통한 인바운드 연결이 필요합니다.
+
Cloud Volumes ONTAP 시스템에 AutoSupport 메시지를 보낼 아웃바운드 인터넷 연결이 없는 경우 콘솔은 콘솔 에이전트에 포함된 프록시 서버를 사용하도록 해당 시스템을 자동으로 구성합니다.  유일한 요구 사항은 콘솔 에이전트의 보안 그룹이 포트 3128을 통한 인바운드 연결을 허용하는 것입니다.  콘솔 에이전트를 배포한 후 이 포트를 열어야 합니다.



--


NTP 활성화:: NetApp Data Classification을 사용하여 회사 데이터 소스를 스캔할 계획이라면 Console 에이전트와 NetApp Data Classification 시스템 모두에서 네트워크 시간 프로토콜(NTP) 서비스를 활성화하여 시스템 간 시간을 동기화해야 합니다 https://docs.netapp.com/us-en/data-services-data-classification/concept-cloud-compliance.html["NetApp Data Classification에 대해 자세히 알아보세요"^].
+
--
콘솔 에이전트를 만든 후 이 네트워킹 요구 사항을 구현해야 합니다.

--

== 2단계: 콘솔 에이전트 배포를 위한 AWS 권한 설정

선택한 인증 방법에 따라 VPC에 Console 에이전트를 배포하는 데 필요한 AWS 권한만 Console에 부여하십시오.

다음 인증 방법 중 하나를 선택하고 필요한 설정만 구성하십시오:

[cols="1a,2a,2a"]
|===
| 방법 | 수행하는 작업 | 설정 내용 


 a| 
*저를 위한 역할 생성*
 a| 
콘솔은 AWS CloudFormation Quick Create를 열어 콘솔이 사용할 배포 역할을 생성합니다.
 a| 
스택을 제출하는 AWS ID에 대한 권한입니다.



 a| 
*역할 수임*
 a| 
콘솔은 사용자 계정의 기존 IAM 역할을 수임합니다.
 a| 
정책 및 IAM 역할.



 a| 
*AWS 키*
 a|

 a|

|===
*Create role for me* 및 *Assume role*을 사용하면 콘솔은 콘솔 에이전트를 배포하기 위해 *배포 역할*이라는 IAM 역할을 수임합니다. 배포 후 콘솔 에이전트는 EC2 인스턴스에 연결된 *에이전트 역할*이라는 별도의 IAM 역할을 사용합니다. 기본적으로 콘솔은 에이전트 역할을 자동으로 생성합니다. link:#aws-agent-role["사용자 고유의 에이전트 역할을 사용하는 방법을 알아보십시오."].

=== 나를 위한 역할 생성(CloudFormation 빠른 생성) 권한 설정

CloudFormation 스택과 배포 역할을 생성할 수 있는 AWS ID를 사용하여 권한 오류 없이 스택이 완료되도록 하십시오.

CloudFormation Quick Create 스택을 제출하는 ID에는 관리자 권한 또는 다음 최소 권한이 필요합니다. 이러한 권한을 통해 CloudFormation이 배포 역할을 생성할 수 있습니다. 이는 에이전트 역할의 권한이 아닙니다.

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationStack",
      "Effect": "Allow",
      "Action": [
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:GetTemplateSummary",
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:GetRole",
        "iam:PutRolePolicy",
        "iam:DeleteRolePolicy",
        "iam:GetRolePolicy",
        "iam:PassRole",
        "lambda:CreateFunction",
        "lambda:DeleteFunction",
        "lambda:GetFunction",
        "lambda:InvokeFunction"
      ],
      "Resource": "*"
    }
  ]
}
----

=== Assume 역할 또는 AWS 키에 대한 권한을 설정합니다

*역할 위임* 또는 *AWS 키*를 선택한 경우, Console 에이전트를 배포하는 데 필요한 권한만 포함된 정책을 생성하고 Console에서 사용하는 역할 또는 사용자에게 연결하십시오.

필요한 경우 IAM을 사용하여 IAM 정책을 제한할 수 있습니다. `Condition` 요소. https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html["AWS 설명서: 조건 요소"^]

.단계
. AWS IAM 콘솔로 이동합니다.
. *정책 > 정책 만들기*를 선택합니다.
. *JSON*을 선택하세요.
. 다음 정책을 복사하여 붙여넣으세요.
+
이 정책에는 콘솔에서 AWS에 콘솔 에이전트를 실행하는 데 필요한 권한만 포함되어 있습니다. link:reference-permissions-aws.html["에이전트 역할의 권한 보기"].

+
[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",
        "iam:RemoveRoleFromInstanceProfile",
        "iam:DeleteInstanceProfile",
        "iam:PassRole",
        "iam:ListRoles",
        "ec2:DescribeInstanceStatus",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:CreateSecurityGroup",
        "ec2:DeleteSecurityGroup",
        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",
        "ec2:DescribeNetworkInterfaces",
        "ec2:DeleteNetworkInterface",
        "ec2:ModifyNetworkInterfaceAttribute",
        "ec2:DescribeSubnets",
        "ec2:DescribeVpcs",
        "ec2:DescribeDhcpOptions",
        "ec2:DescribeKeyPairs",
        "ec2:DescribeRegions",
        "ec2:DescribeInstances",
        "ec2:CreateTags",
        "ec2:DescribeImages",
        "ec2:DescribeAvailabilityZones",
        "ec2:DescribeLaunchTemplates",
        "ec2:CreateLaunchTemplate",
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:ValidateTemplate",
        "ec2:AssociateIamInstanceProfile",
        "ec2:DescribeIamInstanceProfileAssociations",
        "ec2:DisassociateIamInstanceProfile",
        "iam:GetRole",
        "iam:TagRole",
        "kms:ListAliases",
        "cloudformation:ListStacks"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:TerminateInstances"
      ],
      "Condition": {
        "StringLike": {
          "ec2:ResourceTag/OCCMInstance": "*"
        }
      },
      "Resource": [
        "arn:aws:ec2:*:*:instance/*"
      ]
    }
  ]
}
----
. *다음*을 선택하고 필요한 경우 태그를 추가합니다.
. *다음*을 선택하고 이름과 설명을 입력합니다.
. *정책 만들기*를 선택하세요.
. 콘솔이 가정할 수 있는 IAM 역할이나 IAM 사용자에게 정책을 연결하여 콘솔에 액세스 키를 제공할 수 있습니다.
+
** *역할 수임*: 콘솔이 수임할 수 있는 IAM 역할을 설정합니다:
+
... 대상 계정의 AWS IAM 콘솔로 이동합니다.
... 액세스 관리에서 *역할 > 역할 만들기*를 선택하고 단계에 따라 역할을 만듭니다.
... *신뢰할 수 있는 엔터티 유형*에서 *AWS 계정*을 선택합니다.
... *다른 AWS 계정*을 선택하고 콘솔 SaaS 계정의 ID를 입력하세요: 952013314444
... 이전 섹션에서 만든 정책을 선택하세요.
... 역할을 만든 후 역할 ARN을 복사하여 콘솔 에이전트를 만들 때 콘솔에 붙여넣을 수 있습니다.


** *AWS 키*: 콘솔에 액세스 키를 제공할 수 있도록 IAM 사용자에게 권한을 설정합니다:
+
... AWS IAM 콘솔에서 *사용자*를 선택한 다음 사용자 이름을 선택합니다.
... *권한 추가 > 기존 정책을 직접 첨부*를 선택합니다.
... 생성한 정책을 선택하세요.
... *다음*을 선택한 다음 *권한 추가*를 선택합니다.
... IAM 사용자에 대한 액세스 키와 비밀 키가 있는지 확인하세요.






.결과
이제 필요한 권한을 가진 배포 역할 또는 IAM 사용자가 있습니다. Console 에이전트를 배포할 때 역할 ARN 또는 액세스 키를 제공합니다.

== 3단계: 콘솔 에이전트용 IAM 역할을 직접 설정합니다(선택 사항)

Console이 기본적으로 생성하는 역할 대신 선택하려면 고유한 에이전트 역할을 생성하십시오. Console 에이전트를 배포하기 전에 역할을 생성하십시오.

.단계
. AWS 콘솔에 로그인하고 IAM 서비스로 이동합니다.
. 정책을 만듭니다.
+
.. *정책 > 정책 만들기*를 선택합니다.
.. *JSON*을 선택하고 내용을 복사하여 붙여넣습니다.link:reference-permissions-aws.html["콘솔 에이전트에 대한 IAM 정책"] .
.. 나머지 단계를 완료하여 정책을 만듭니다.
+
표준 지역의 경우 권한은 두 가지 정책에 걸쳐 분산됩니다.  AWS의 관리형 정책에는 최대 문자 크기 제한이 있으므로 두 개의 정책이 필요합니다. link:reference-permissions-aws.html["콘솔 에이전트에 대한 IAM 정책에 대해 자세히 알아보세요."] .



. IAM 역할을 만듭니다.
+
.. *역할 > 역할 만들기*를 선택합니다.
.. *AWS 서비스 > EC2*를 선택합니다.
.. 방금 만든 정책을 첨부하여 권한을 추가합니다.
.. 나머지 단계를 완료하여 역할을 만듭니다.




.결과
이제 Console 에이전트를 배포할 때 *에이전트 배포 세부 정보*에서 선택할 수 있는 에이전트 역할이 있습니다.



[[step-4-deploy-the-console-agent]]
== 4단계: 콘솔 에이전트 배포

콘솔이 VPC에서 콘솔 에이전트를 시작할 수 있도록 인증, 배포, 네트워크 및 보안 그룹 세부 정보를 제공하십시오.

.이 작업에 관하여
* 콘솔에서 콘솔 에이전트를 생성하면 기본 구성을 사용하여 AWS에 EC2 인스턴스가 배포됩니다.  콘솔 에이전트를 생성한 후에는 CPU나 RAM이 적은 더 작은 EC2 인스턴스로 전환하지 마세요. link:reference-agent-default-config.html["콘솔 에이전트의 기본 구성에 대해 알아보세요"] .
* 기본적으로 콘솔은 에이전트 역할과 해당 프로필을 생성합니다. 사용자 지정 에이전트 역할을 제공하는 경우 향후 릴리스에서 새 권한이 추가될 때마다 해당 역할을 업데이트해야 합니다. link:reference-permissions-aws.html["콘솔 에이전트에 대한 IAM 정책에 대해 자세히 알아보세요."].


.시작하기 전에
다음 사항이 있어야 합니다.

* AWS 인증 방법: *역할 생성*, *역할 위임* 또는 *AWS 키*.
* 네트워킹 요구 사항을 충족하는 VPC 및 서브넷.
* EC2 인스턴스에 대한 키 쌍입니다.
* 콘솔 에이전트에서 인터넷에 접속하는 데 프록시가 필요한 경우 프록시 서버에 대한 세부 정보입니다.
* 완료됨 link:#networking-aws-agent["1단계"].
* 완료됨 link:#aws-permissions-agent["2단계"].


.단계
. *관리 > 에이전트*를 선택하세요.
. *개요* 페이지에서 *에이전트 배포 > AWS*를 선택합니다.
. *에이전트 배포용 AWS 자격 증명* 섹션에서 다음 인증 방법 중 하나를 선택하십시오:
+
** *저를 위한 역할 생성*:
+
... AWS 리전을 선택하고 AWS 계정 ID를 입력하십시오. 필요에 따라 외부 ID를 입력하십시오.
... *CloudFormation 빠른 생성 열기*를 선택합니다.
... AWS에서 약관에 동의하고 *스택 생성*을 선택하세요.
... AWS에서 역할 생성이 완료되면 콘솔로 돌아가서 역할을 확인하십시오.


** *역할 수임*: IAM 역할의 ARN을 입력하고 *자격 증명 확인*을 선택합니다.
** *AWS 키*: 액세스 키와 비밀 키를 입력하고 *자격 증명 확인*을 선택하십시오.


. *에이전트 배포 세부 정보* 섹션에서 Console 에이전트에 대한 세부 정보를 제공하십시오.
+
** 이름을 입력하세요.
** 사용자 정의 태그(메타데이터)를 추가합니다.
** 콘솔에서 에이전트 역할을 생성하도록 할지, 아니면 사용자가 link:#aws-agent-role["직접 설정하세요"] 에이전트 역할을 선택할지 선택하십시오.
** 콘솔 에이전트의 EBS 디스크를 암호화할지 여부를 선택합니다.  기본 암호화 키를 사용하거나 사용자 지정 키를 사용할 수 있습니다.


. *네트워킹 구성* 섹션에서 Console 에이전트에 사용할 VPC, 서브넷 및 키 페어를 지정하고, 공용 IP 주소를 활성화할지 여부를 선택하며, 선택적으로 프록시 구성을 지정합니다.
+
콘솔 에이전트 가상 머신에 액세스하려면 올바른 키 쌍이 있는지 확인하세요.  키 쌍이 없으면 액세스할 수 없습니다.

. *보안 그룹* 섹션에서 새 보안 그룹을 생성할지, 아니면 필요한 수신 및 발신 규칙을 허용하는 기존 보안 그룹을 선택할지 선택합니다.
+
link:reference-ports-aws.html["AWS에 대한 보안 그룹 규칙 보기"] .



. 선택 사항을 검토하여 설정이 올바른지 확인하십시오.
+
.. *에이전트 구성 검증* 확인란은 배포 시 NetApp Console에서 네트워크 연결 요구 사항을 검증하도록 기본적으로 선택되어 있습니다. NetApp Console에서 에이전트 배포에 실패하면 문제 해결에 도움이 되는 보고서를 제공합니다. 배포가 성공하면 보고서는 제공되지 않습니다.


+
[NOTE]
====
** link:reference-networking-saas-console-previous.html["이전 종료점"]에이전트 업그레이드에 사용되는 방식을 계속 사용하는 경우 유효성 검사가 오류와 함께 실패합니다. 이를 방지하려면 확인란을 선택 해제하여 유효성 검사를 건너뜁니다.
** 설치 과정에서 NetApp은 에이전트 호스트에 전체 디스크 공간의 최소 80%가 사용 가능한지 확인합니다. 여기에는 `/opt`에 48GB와 `/var`에 32GB(총 80GB)가 포함됩니다. 설치 후에는 전체 디스크 공간의 최소 20%가 사용 가능한 상태로 유지되어야 하며, 여기에는 `/opt`에 12GB와 `/var`에 8GB(총 20GB)가 포함됩니다.


====
. *추가*를 선택하세요.
+
콘솔에서 콘솔 에이전트를 배포하는 데 약 10분이 소요됩니다. 프로세스가 완료될 때까지 이 페이지를 그대로 유지하십시오.



.결과
프로세스가 완료되면 콘솔 에이전트를 콘솔에서 사용할 수 있습니다.

콘솔 에이전트를 생성한 동일한 AWS 계정에 Amazon S3 버킷이 있는 경우, *시스템* 페이지에 Amazon S3 작업 환경이 자동으로 표시됩니다. https://docs.netapp.com/us-en/storage-management-s3-storage/index.html["NetApp Console 에서 S3 버킷을 관리하는 방법을 알아보세요."^]

== 콘솔 에이전트 배포 실패 문제 해결

배포 보고서를 사용하여 Console 에이전트 배포를 차단한 원인을 찾은 다음 다시 시도하십시오.

콘솔은 *에이전트 구성 검사* 확인란이 선택된 경우에만 보고서를 제공합니다. 배포가 성공하면 보고서가 생성되지 않습니다.

.단계
. *에이전트 배포 실패* 대화 상자에서 *보고서 다운로드*를 선택합니다.
+
콘솔은 유효성 검사 보고서가 포함된 PDF 파일을 다운로드합니다.

. 보고서를 검토하고 보고서에 나열된 문제점을 해결하십시오.
. 대화 상자에서 *다시 시작*을 선택한 다음 배포를 다시 완료하십시오.
+
다시 시도하려면 전체 과정을 처음부터 다시 시작해야 합니다.



link:task-troubleshoot-agent.html#troubleshoot-installation["설치 문제를 해결하는 방법을 알아보세요."]
